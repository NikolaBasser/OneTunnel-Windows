OneTunnel — Windows x64

APPLICATION VERSION
0.1.0. The Go core is versioned separately and pinned by core-reference.json.

BUILD REQUIREMENTS
Windows 10/11 x64, .NET 10 SDK and PowerShell.
An explicitly selected clean core bundle matching core-reference.json is required.
Assets and dependency license notices are included in the source tree.

PREPARE THE CORE INPUT
Read core-reference.json and check out that exact commit in the separate OneTunnel-Core repository.
Follow its BUILD.txt to produce a clean Windows amd64 core bundle.
This repository contains no Go sources, Go setup script or implicit core build command.

BUILD THE WINDOWS APPLICATION
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1 -Name OneTunnel-0.1.0-win-x64 -CoreBundlePath C:\path\to\trusted-core-bundle
For a development build:
dotnet build OneTunnel.csproj -p:CoreBundlePath=C:\path\to\trusted-core-bundle
Application builds never compile or download Go binaries implicitly.
Bundle validation checks API, platform, native architecture and file integrity before packaging.
Use bundles produced from reviewed source; self-reported hashes do not authenticate a publisher.
The selected core must match the pinned version, source revision, API and target and be clean.
Updating core-reference.json is a reviewed dependency update, not an automatic latest-version selection.
The selected manifest is included in the application output as core-bundle.json.

SUPPORTED TARGETS
The complete application and embedded native dependencies currently support Windows x64.
Portable core tests belong to the separate core repository. Windows ARM64 requires matching
native dependencies and runtime validation before it can be packaged. No release is produced by CI.

CI
Push and pull-request checks run synthetic source/bundle-validator checks only; they are not application builds.
The manual Windows package workflow explicitly checks out and builds the pinned core source.
Before running it, configure ONETUNNEL_CORE_REPOSITORY as the trusted owner/repository and
CORE_READ_TOKEN as a read-only token for that private repository. Missing configuration fails
the build job. No remote repository is assumed or created by this local split.

ISOLATED WORKSPACE CHECK
Run with the service idle (or absent). The check does not disconnect an existing session.
powershell -NoProfile -Command "dotnet run --project tests/WorkspaceUi.Check/WorkspaceUiCheck.csproj -c Release -r win-x64 -p:CoreBundlePath=C:\path\to\trusted-core-bundle"
The check creates a new temporary synthetic profile store and prints its capture directory.
It does not connect a tunnel, probe servers, install a service or change the real profile store.

SAVED SUBSCRIPTIONS
The Subscriptions page lists saved groups without displaying their private source URLs.
Check for updates downloads a preview; Apply commits that exact reviewed result.
Cancel or a cancelled download does not apply changes. Previews expire after ten minutes;
an intervening profile or group change requires a fresh preview.
Provider-reported traffic and expiry may be unknown and do not establish live usage accuracy.
Scheduled refresh is not included. Existing import and connect-time preparation still work.
Manual subscription management runs in the user host and requires no service update.

SYSTEM TRAY
Right-click the OneTunnel notification-area icon for the Go-projected status and actions.
Open or double-click restores the existing window. Minimize retains its taskbar entry.
The recovery menu opens the existing view; it does not change networking automatically.
Status notifications are off by default. The tray menu can enable them for this session;
Windows notification preferences may suppress delivery. This choice is not persisted.
Close/Exit retains the normal UI-exit behavior and does not disconnect the service.
This UI-only feature requires no installed-service update.

OUTPUT
dist/OneTunnel-0.1.0-win-x64/
dist/OneTunnel-0.1.0-win-x64.zip

SERVICE INSTALLATION
The package contains a native Go installer; scripts/Install-Service.ps1 is a compatibility launcher.
Administrative PowerShell:
  ./OneTunnel.Profiles.exe --install-service <interactive-user-SID>
The owner's SID is available from whoami /user in the intended user's session.
The installer accepts updates only when the service has no active session
or pending traffic protection.

RUN
OneTunnel.exe in the package directory.
The package includes the .NET runtime, user profile host and Go service.
Servers and access credentials are configured separately in the application.
The separate minimize-to-tray button hides the window. Restore it from the tray
or with Ctrl+Shift+O. This shortcut is registered only while the window is hidden;
if registration fails, the window stays visible. Ordinary minimize keeps its
taskbar entry. Explorer restart restores an explicitly hidden window.
Status notifications can be enabled in the window or tray for the current session.
They are off by default and are not saved between application launches.
The Events page offers explicit diagnostics generation, preview, copy and JSON save.
The report identifies the bundled profile host, not the installed service; engine
availability hints do not test runtime health. Generation makes no network requests.
No report is created, copied, saved or uploaded automatically. A service update is
not required for this user-host feature.
